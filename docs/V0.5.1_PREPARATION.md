## 1. 已修复问题

- **待测对象身份**：复制前检查目标/依赖 basename（忽略大小写）、plugin name、`provides` alias 和 probe 保留名称。目标/依赖/Paper 复制后校验 SHA-256。probe 对照本次运行 ID、名称、版本、主类以及实际 CodeSource 路径；只接受目标隔离 JAR 或该隔离目录内同名 `.paper-remapped` JAR，不接受另一个依赖的类来源。依赖 hash、运行配置及末次 probe 完整字段进入 runtime report。
- **稳定窗口**：从 ready 后首个有效 enabled 样本开始计时。schema、序列、更新时间必须有效，序列与时间递增，主机观察间隔和快照时间偏差均不得超过 2 秒；窗口结束后还须取得新样本并追上日志。单快照、重复序列的 touch/重写、回退序列/时间、错误运行 ID、错误身份、读取失败和未完成窗口不能 PASS。身份错误不会被后续样本清除；Java probe 锁存目标 disable 事件。零窗口在 CLI、Matrix 配置和运行入口明确拒绝。
- **日志与进程**：stdout/stderr 直接写原始二进制 `server.log`，容错解码只用于解析，无日志线程退出/EOF 提前完成路径。每次读取和父进程退出后的 drain 均有界。Windows 在恢复挂起进程前加入 Job Object，终止 Job 后等待 active process 数归零；POSIX 独立 session/process group，SIGKILL 并有界等待。日志/清理异常不会 PASS。
- **日志归因**：其他插件 logger、名称子串和“Other 缺少目标依赖”的异常不会直接归因目标；enable/load 错误按明确主体判定。保留目标 enable failure 和 disable 的原始证据。
- **路径与写入**：报告保护包括配置、目标、依赖、Paper 和日志，早期预检失败也保留待保护输入。拒绝 work/cache 重叠、输入位于可变输出根、报告位于 work/cache、符号链接和 Windows reparse/junction 输出路径。报告、下载和 cache 文件复制使用临时文件+原子替换；cache 目标端硬链接不会修改外部原文件。Paper API 文件名、checksum 与嵌入库路径均校验，现有 checksum 错误缓存保留并明确报错。
- **Matrix**：单环境 result.json 保存异常变成 report 阶段 UNKNOWN_FAILURE，保留日志/目录和原 verdict 元数据，继续后续环境并生成汇总，退出码为 3。
- **输入边界**：JAR 压缩文件/总解压量最多 512 MiB、最多 100000 entries、plugin.yml 最多 1 MiB；支持 STORED/DEFLATED，拒绝重复、加密、未知/不支持压缩及损坏条目。Paper 嵌入库总量最多 512 MiB、单项最多 256 MiB、路径不能穿越或使用 Windows 设备名。descriptor 支持行内注释、引号中的 #、三段 api-version；缺少版本、重复关键字段、不支持的 YAML、双 descriptor 明确拒绝。
- **workflow/版本**：输入仅经 env 传入；解析真实 workspace 边界，保护 `.ci` 输出，完整转义错误消息，最终退出码通过 env 和数字白名单处理。权威版本为 `0.5.1`，CHANGELOG 已记录 2026-09-13 发布日。CI 增加 Windows/Linux × Python 3.10/3.11 离线检查。

## 2. 原有未提交修复的不完整之处

- 将 mtime/内容指纹当成 probe 更新，允许没有 sequence 的旧快照；sequence 回退和同序列重写不被拒绝。
- 新鲜度只在末端检查，且依赖 expected_version；短窗口可以只用一个样本，窗口从 ready 开始而非有效 enabled 样本开始。
- 身份不匹配可被后续有效样本清除，未检查运行 ID、主类或实际来源；缺版本被放宽而不是明确拒绝。
- `RuntimeEvidence` 未完成标志默认 None，直接 verdict 仍能绕过完整窗口；旧成功测试只提供日志/单快照。
- 退出后的 `while read_log()` 可被仍活着的后代持续输出拖住；Windows 关闭 Job handle 后只等待父进程，未确认全部 active processes 归零。
- cache 仅拒绝源树 symlink，目标树链接/硬链接、祖先 junction、嵌入库 Windows 路径和 API basename 检查不完整。
- 早期失败的 metadata 可能缺少应保护输入；单环境 report 与 work/cache artifact 的保护不完整。
- 日志中的目标边界匹配仍会把“其他插件依赖目标”的异常归因错误。
- workflow 输入解析加固后，固定 `.ci/plugin.jar`/`.ci/matrix.json` 输出仍可能覆盖输入或跟随链接；safe_error 只转义 raw 字段而未转义 detail。旧测试甚至靠注释中的 `cp --` 字符串通过，未执行脚本。
- 冲突回归用零稳定窗口且只断言 ENVIRONMENT_INVALID，可能因其他配置错误通过。已改为正数窗口，并断言冲突原因和未进入下载/Java。
